### Store depth teacher weights at their CUDA precision

I profiled the teacher call at `f58f7fb9` with real checkpoints and decoded OMX frames.

You can reduce teacher memory with one conversion in `DistillationTeachers.__init__`.
Store depth `Linear` and `Conv2d` weights and biases at the precision their CUDA operations already use.
MoGe uses 16-bit floating point (`FP16`). MoRGBD uses `bfloat16` (`BF16`).
Load each model on the CPU, convert these parameters, then transfer the model to CUDA.
Normalization, positions, geometry and the video teacher retain their original precision.

For the selected parameters, the change removes per-call casts:

```text
Original: FP32 CPU -> FP32 GPU -> cast for each call -> FP16/BF16
Proposed: FP32 CPU -> cast once -> FP16/BF16 GPU
```

The actual source patch gives these NVIDIA L4 results:

| Measurement | Original | Proposed |
|---|---:|---:|
| Constructor peak allocated memory | 2.09 GiB | 1.35 GiB |
| Warmed target peak, batch 1 | 2.94 GiB | 1.43 GiB |
| Complete target median, batch 1 | 84.85 ms | 74.84 ms |
| Complete target median, batch 4 | 242.36 ms | 233.90 ms |

Batch-one teacher time falls by **11.8%**. Its isolated memory peak falls by **51.3%**.
The study uses 24 measured calls per variant after four warmup calls per variant.
Each pair uses a random variant order. Separate memory measurements retain only the active teacher bundle on CUDA.

### Numerical checks

All 1,233 teacher parameters and six buffers match the required conversion in value, dtype and stride.
All 25 target comparisons match exactly across four real frame pairs at batch sizes one and four.
These checks include `future_video_cls`.

I also test the exact helper through the native 6B training entry point on an NVIDIA H200.
One optimizer update produces identical teacher targets, clipped gradients, updated model parameters and AdamW state.
The inputs and initial model parameters match. All captured tensors remain finite.

This equality check uses `torch.use_deterministic_algorithms(True)`, `cudnn.deterministic=True`, `cudnn.benchmark=False`, and `CUBLAS_WORKSPACE_CONFIG=:4096:8`.
With default settings, two unchanged native baselines also produce different depth targets, with `max_abs=0.25`.
The [PyTorch reproducibility guide](https://docs.pytorch.org/docs/2.11/notes/randomness.html#cuda-convolution-benchmarking) explains variation in convolution algorithm selection.

Native update timing does not show a consistent gain across the two short comparisons.
The proposal therefore rests on the measured teacher memory reduction and teacher-stage time reduction.
